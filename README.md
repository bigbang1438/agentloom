# AgentLoom · 受约束的工具调用 Agent 平台

Python 3.12 + FastAPI 实现的生产形态 Agent 服务，重点解决四件事：
**模型输出不可信、预算失控、依据造假、出了事没法复盘**。

> **零配置可跑**：不配 API Key 时用内置确定性脚本模型，`git clone` 后直接
> `pytest` 全绿、起服务就能看到完整的「模型决策 → 工具执行 → 结果回灌 → 作答」链路。
> 配好 Key 后同一个循环切到 OpenAI / DeepSeek 等兼容后端，代码不用改。
>
> 这是一个**个人工程实践项目**，用于学习和演示，不是实习、商业上线或生产团队使用经历。

## 解决的四个工程问题

### 1. 模型输出不可信

`ToolRegistry.invoke()` 是唯一工具入口，四道校验：

| 闸门 | 挡什么 |
| --- | --- |
| 工具白名单 | 模型臆造工具名 |
| 参数必须是 JSON 对象 | 类型错乱输入 |
| **未声明字段一律拒绝** | 参数走私（`additionalProperties: false`） |
| 必填 / 类型 / 枚举 / 长度 / 范围 | 畸形参数 |

**校验失败不抛异常**，而是转成「拒绝观察结果」回灌给模型，
让它知道错在哪、换个做法——既守住边界，又不炸循环。

### 2. 预算失控

五维预算：`max_steps` / `max_model_turns` / `max_tool_calls` / `timeout` / `token`+成本。
超预算**不返回 500**，而是返回结构化 `stopped_reason` + `truncated` 标志，
让调用方区分「被截断」（可放宽预算重试）与「失败」（要排查上游）。

### 3. 写操作自己批准自己

**结构性隔离，不是提示词约束**：

- 工具白名单里**不存在**审批工具，模型没有批准入口
- 写工具只产生待确认请求，审批走独立 HTTP 接口由人触发
- 确认编号绑定具体参数，**只能消费一次**（防重放）
- 没配置审批人时写操作**默认拒绝**

### 4. 依据造假（假引用）

检索 → 服务端分配 `[1]…[n]` 编号 → 编号+原文进上下文 → 模型作答 →
抽取答案里的 `[n]` 与合法编号比对 → **越界即拦截**。

一个编造的引用比没有引用更危险：没有引用读者知道是模型说法，
有了一个看起来很像的引用，读者会以为有依据。
这是把不可靠性伪装成可靠性。

**边界（不夸大）**：编号合法**只证明**指向真实片段，
**不证明**每句话都被该片段支持。语义支持需要人工或模型复核，这里没做。

## 检索设计：BM25 + 两道精度闸门

选词法检索不用向量库，是为了**零依赖、结果可解释、行号可溯源**。
代价是处理不了语义改写，这个边界写清楚不掩饰。

在标准 BM25（k1=1.5, b=0.75）之上加两道闸门：

1. **停用词过滤**：中文虚词组成的二元词组（「怎么」「什么」）不参与打分
2. **查询覆盖率门槛**（`min_coverage=0.25`）：查询里有信息量的词命中比例过低不算证据

**阈值是扫出来的，不是拍的**：

| min_coverage | Recall@1 | Recall@3 | MRR@3 | 无答案拒答 |
| ---: | ---: | ---: | ---: | ---: |
| 0.00 | 0.92 | 1.00 | 0.960 | 2/4 |
| 0.10 | 0.90 | 1.00 | 0.952 | 3/4 |
| 0.20 | 0.90 | 0.97 | 0.935 | 3/4 |
| **0.25** | **0.94** | **0.97** | **0.952** | **4/4** |
| 0.35 | 0.74 | 0.81 | 0.774 | 4/4 |

0.25 是拒答满分与召回不掉的交点；0.35 起开始误杀正确答案。

中文分词用**二元词组** + 单字降权（0.15）：
「工具调用」切成 `工具`/`具调`/`调用`，单字保留但降权。
额外规则：只有单字重合的片段不算证据，否则「的」「是」会把无关片段全捞上来。

## 评测的诚实边界

`eval/report.json` 的数字真实可复现，但**不能**当通用能力指标：

- 数据集**小且公开**（3 份文档、31 正例 + 4 负例），题目与资料同源，等于开卷考试
- 这是**检索指标**，不是 LLM 问答准确率
- 行号可追溯 ≠ 引用语义支持
- 没有盲测，没有独立保留集

数据集用**内容锚点**标识黄金片段（不是硬编码行号）：
文档增删行不会让数据集失效，锚点找不到时**直接报错**而非静默降级。

## API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 存活 + 模型后端 + 资料统计 |
| GET | `/api/state` | 工具清单、资料、待确认项、CSRF token |
| GET | `/api/tools` | 工具的 JSON Schema |
| POST | `/api/ask` | 跑完整循环，返回答案 + 逐步轨迹 + 引用 |
| POST | `/api/ask/stream` | 同上，SSE 逐事件推送 |
| POST/GET | `/api/documents` | 导入 / 列出知识库文档 |
| POST | `/api/search` | 直接暴露检索（不经模型，便于评测） |
| GET/POST | `/api/approvals[/{id}]` | 待确认写操作的审批 |
| GET | `/api/runs[/{id}]` | 运行轨迹持久化与回读 |
| GET | `/metrics` | 运行数、工具调用、拒绝数、P50/P95/P99、成本 |

安全中间件：Host / Origin 校验、写请求 CSRF token、请求体大小上限、
错误响应不含堆栈（堆栈只进服务端日志）。

## 已知边界（不夸大）

- **没有对真实模型做效果评测**。脚本模型是确定性桩，不代表任何模型能力
- **没有鉴权**。默认只绑 `127.0.0.1`，对外暴露前必须自己加认证与限流
- **`/metrics` 是进程内计数**，多副本下各自独立，没有聚合
- **没有长记忆**。会话历史由调用方传入，服务端只持久化轨迹用于复盘
- **没有多租户**。单用户本机应用，没有账号体系
- **SQLite 单文件**，没有连接池与读写分离
