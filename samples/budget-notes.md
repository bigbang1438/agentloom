# 预算与停止条件

## 为什么必须有预算

一个没有预算的 Agent 在生产环境里是事故源：

- 模型可能陷入「调用工具 → 结果不满意 → 再调用」的死循环，账单无限增长。
- 一个慢工具可能拖住整个请求，占满连接池。
- 用户点一次按钮，可能触发几十次模型调用。

预算不是「优化」，是**上线前提**。

## 五维预算

| 维度 | 默认值 | 作用 |
| --- | --- | --- |
| `max_steps` | 12 | 模型轮次 + 工具调用的合计上限 |
| `max_model_turns` | 8 | 模型被调用的次数上限 |
| `max_tool_calls` | 12 | 工具执行总数上限 |
| `timeout_seconds` | 60 | 整体墙钟时间上限 |
| `max_tokens` | 60000 | 累计 token 上限 |
| `max_cost_usd` | 0.50 | 估算成本上限 |

## 停止原因是结构化输出

超预算时**不抛 500**。返回体里带一个 `stopped_reason` 字段：

| 值 | 含义 | 调用方该怎么做 |
| --- | --- | --- |
| `completed` | 正常收敛 | 直接用答案 |
| `max_steps` | 步数用尽 | 可放宽预算重试 |
| `max_tool_calls` | 工具调用用尽 | 可放宽预算重试 |
| `timeout` | 超时 | 检查工具是否太慢 |
| `max_tokens` | token 用尽 | 检查上下文是否过长 |
| `max_cost` | 成本超限 | 检查是否有死循环 |
| `model_error` | 模型调用失败 | 排查上游服务 |
| `guardrail` | 被护栏拦截 | 检查输入内容 |
| `cancelled` | 被主动取消 | 无需处理 |

同时返回 `truncated: true/false`，让调用方一眼区分
「被截断」（可以重试）和「失败」（要排查）。

## 成本估算

按 token 用量乘单价估算，单价可配置。默认值取通用兼容后端的保守量级。
估算值用于**防失控**，不是精确账单——真实计费以供应商为准。
